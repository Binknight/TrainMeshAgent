# TrainMesh Agent 使用指南

## 1. 产品概述

TrainMesh Agent 是一款面向 AI 训练组网仿真测试的智能助手系统。它帮助测试人员：

- **输入组网参数** — 设备类型 (A2/A3/A5)、并行策略 (DP/TP/PP)、模型架构参数
- **生成组网拓扑** — 可视化原始组网与等效组网的 Mesh 结构
- **构建模型结构** — 自动生成 Transformer 模型层级描述
- **推送等效分析** — 逐条展示等效策略、计算指标与公式
- **执行仿真验证** — 通过 MCP 客户端下发仿真任务、实时监控进度
- **等效性判定** — 自动对比原始组网与等效组网仿真结果，输出结论

系统采用 **Flask 后端 + 静态前端 + OpenAI LLM + MCP 仿真** 的四层架构。

---

## 2. 系统架构

```
┌──────────────┐     SSE/REST/WS      ┌──────────────────────┐     JSON-RPC      ┌─────────────┐
│  前端 (SPA)   │ ──────────────────→ │  Flask Agent 后端     │ ──────────────→ │ MCP 仿真服务 │
│  index.html   │                      │  orchestrator + skills│                  │  (端口 9000) │
└──────────────┘                      └──────────────────────┘                  └─────────────┘
                                            │          │
                                      OpenAI API     PostgreSQL
                                      (LLM 推理)     (持久化)
```

核心组件：

| 目录 | 功能 |
|------|------|
| `app/routes/` | REST/WebSocket 路由（session、chat、simulation、model_catalog） |
| `app/agent/` | Agent 编排：orchestrator（LLM 驱动循环）、session（状态管理）、guardrails（护栏校验） |
| `app/skills/` | 注册式技能：组网生成、模型生成、仿真分析 |
| `app/mcp/` | MCP 客户端：JSON-RPC 调用仿真系统的任务下发/状态查询/结果获取 |
| `app/models/` | Pydantic 数据模型 + 模型目录（HuggingFace 远程解析） |
| `app/dao/` | PostgreSQL 数据访问层 |
| `static/` | 前端单页应用（HTML/CSS/JS + 拓扑渲染 + 仿真数据流） |

## 3. 环境准备

### 3.1 依赖安装

```bash
pip install -r requirements.txt
```

核心依赖：

| 包 | 用途 |
|----|------|
| `flask` + `flask-cors` + `flask-sock` | Web 服务 + CORS + WebSocket |
| `openai` | LLM SDK（调用大语言模型） |
| `pydantic` | 数据校验与序列化 |
| `psycopg2-binary` | PostgreSQL 连接池 |
| `requests` | MCP JSON-RPC 调用 |
| `python-dotenv` | 环境变量加载 |

### 3.2 PostgreSQL 数据库

创建数据库并配置连接串：

```sql
CREATE DATABASE train_mesh_agent;
```

应用启动时自动执行建表迁移（`app/db_migration.py`），创建以下表：

| 表 | 用途 |
|----|------|
| `sessions` | 会话（步骤、任务 ID） |
| `topology_params` | 拓扑参数（DP/TP/PP、模型维度） |
| `simulation_params` | 仿真脚本与配置 |
| `simulation_results` | 仿真结果（cards JSON） |
| `comparison_reports` | 等效性对比报告 |
| `conversation_messages` | 对话消息记录 |
| `model_catalog` | 模型架构参数目录 |

所有主键均为 UUID（`gen_random_uuid()`），`IF NOT EXISTS` 保证重复执行安全。

### 3.3 MCP 仿真服务

TrainMesh Agent 通过 MCP 协议与独立仿真系统通信。仿真服务需先启动并在指定端口提供以下工具：

| MCP 工具 | 说明 |
|----------|------|
| `execute_task` | 下发仿真任务，返回 `task_id` |
| `report_status` | 查询任务状态与进度 |
| `sync_logs` | 增量同步仿真日志 |
| `get_result` | 获取完整仿真结果 |
| `card_detail` | 获取每卡仿真指标 |
| `get_device_detail` | 获取设备算子追踪与时间线 |
| `get_hbm_detail` | 获取 HBM 使用量拆解 |
| `get_comm_detail` | 获取 TP/PP/DP 通信详情 |

## 4. 配置说明

所有配置通过环境变量管理（支持 `.env` 文件），定义在 `app/config.py`：

| 变量 | 默认值 | 说明 |

| `OPENAI_API_KEY` | *(必填)* | LLM API 密钥 |

| `OPENAI_MODEL` | `gpt-4o` | 使用的模型名称 |

| `MCP_SERVER_URL` | `http://localhost:9000` | MCP 仿真服务地址 |
| `DATABASE_URL` | `postgresql://postgres:postgres@127.0.0.1:5432/train_mesh_agent` | PG 连接串 |
| `FLASK_HOST` | `0.0.0.0` | 服务监听地址 |
| `FLASK_PORT` | `5000` | 服务端口 |
| `FLASK_DEBUG` | `false` | 调试模式 |
| `SIM_POLL_INTERVAL` | `1.0` | 仿真轮询间隔（秒） |

**护栏参数**（硬编码，可修改 `config.py`）：

| 参数 | 值 | 说明 |
|------|---|------|
| `VALID_DEVICE_TYPES` | `{A2, A3, A5}` | 支持的设备类型 |

## 7. 工作流程

Agent 驱动四步工作流，每步等待用户确认后推进：

### Step 1 — 等效参数设定

1. 用户输入组网参数（设备类型、DP/TP/PP）和模型名称
2. **模型参数自动填充**：Agent 调用 `auto_fill_model_params`，通过 HuggingFace → ModelScope → 内置表的四级解析链获取模型架构参数 (L/H/A/dff/V)，推送到前端表单
3. 护栏静默校验参数合法性
4. 调用 `training-mesh-gen-skill` 生成原始组网拓扑
5. 调用 `training-model-gen-skill` 生成原始模型结构
6. 前端渲染组网图 + 模型层级图

### Step 2 — 等效计算推导

1. 用户确认等效计算
2. Agent 逐条推送等效策略、计算指标、公式（`emit_formula_line`），前端逐行渲染
3. 计算等效组网参数（调整 PP/DP/层数等）
4. 生成等效组网拓扑 + 等效模型结构
5. 前端渲染等效组网图

### Step 3 — 等效仿真验证

1. 用户确认下发仿真
2. MCP 客户端下发仿真任务（原始 + 等效）
3. WebSocket 实时推送仿真状态与进度
4. 仿真完成后获取每卡指标（FLOPs、HBM、TP/PP/DP 通信量）

### Step 4 — 等效方案输出

1. 自动对比原始与等效仿真结果
2. 计算各指标差异百分比（容忍度 5%）
3. 输出等效性结论：✅ 通过 或 ❌ 不通过

## 8. 模型参数解析

模型架构参数的获取采用四级解析链（`resolve_model_config`）：

| 级别 | 来源 | 说明 |
|------|------|------|
| 1 | PostgreSQL `model_catalog` | 已入库模型（管理端新增 + 远程导入 + 启动种子） |
| 2 | 本地 JSON 缓存 | `.model_cache/` 目录下的离线缓存文件 |
| 3 | 远程获取 | HuggingFace → ModelScope（完整仓库 ID 直接获取；裸名通过 HF 搜索匹配） |
| 4 | 内置模糊匹配 | 离线兜底表（Qwen3-32B、LLaMA 系列等） |

**仅支持稠密模型**。MoE/稀疏模型（Mixtral、DeepSeek-V2/V3 等）会被检测并标记为 `model_type=sparse`，前端收到后提示不支持。

## 9. 护栏校验

输入护栏（`validate_input_params`）在 Agent 调用工具时静默执行：

- **设备类型**：仅允许 A2、A3、A5
- **DP 范围**：1–1024（>512 发警告）
- **TP 范围**：1–32（非 2 的幂次发警告）
- **PP 范围**：1–128
- **总节点数**：= DP × TP × PP，>10000 发警告

输出护栏（`validate_topology_output`）校验生成拓扑的一致性：

- 节点数 = `total_nodes` = DP × TP × PP
- 通信域分组大小与并行度匹配

## 11. 数据模型概览

### 会话状态 (`SessionState`)

```
session_id          — 会话标识 (8字符 UUID)
step                — 当前阶段: idle | params_collected | equiv_calculating | equiv_generated | simulating | completed
original_params     — 原始拓扑参数
equivalent_params   — 等效拓扑参数
original_topology   — 原始组网拓扑 (MeshTopology)
equivalent_topology — 等效组网拓扑
original_training_model   — 原始模型结构 (TrainingModel)
equivalent_training_model — 等效模型结构
original_simulation  — 原始仿真结果 (SimulationResult)
equivalent_simulation — 等效仿真结果
comparison_report   — 对比报告 (ComparisonReport)
simulation_params   — 仿真配置 (SimulationParams)
history             — 对话历史
```

### 组网拓扑 (`MeshTopology`)

```
name             — 组网名称
device_type      — A2 / A3 / A5
total_nodes      — 总节点数 = DP × TP × PP
dp_size / tp_size / pp_size
nodes            — 节点列表 (MeshNode: id, device_type, dp_rank, tp_rank, pp_rank, global_rank)
communication_groups — 通信域分组 {dp: [...], tp: [...], pp: [...]}
```

### 每卡指标 (`CardMetrics`)

```
card_id / global_rank
flops_per_card   — 单卡 FLOPs
hbm_gb           — HBM 总占用
hbm_model_gb     — 模型显存占用 (权重+梯度+优化器)
tp_comm_gb_per_micro  — TP 通信量
pp_comm_mb_per_micro  — PP 通信量
dp_comm_gb_per_step   — DP 通信量
```

### 等效性报告 (`ComparisonReport`)

```
flops_diff_pct / hbm_diff_pct / tp_comm_diff_pct / pp_comm_diff_pct / dp_comm_diff_pct
is_equivalent    — 是否等效 (所有指标差 ≤ 5%)
error_tolerance_pct — 容忍度阈值 (默认 5%)
details          — {conclusion: "✅/❌", max_diff_pct: ...}
```

## 12. 常见问题

### Q: 启动时报数据库连接失败

确保 PostgreSQL 已启动，且 `DATABASE_URL` 配置正确。连接池默认 2–10 连接（`app/db.py`）。

### Q: 模型参数填充失败

1. 检查网络是否可访问 HuggingFace (`huggingface.co`)
2. 尝试使用完整仓库 ID（如 `Qwen/Qwen2.5-7B`）而非裸名
3. 裸名会先搜索 HF 匹配官方仓库，再走远程获取
4. 最终兜底为内置种子表

### Q: 仿真任务下发失败

1. 确认 MCP 仿真服务已在 `MCP_SERVER_URL` 端口启动
2. 检查服务健康状态：`GET <MCP_SERVER_URL>/health`
3. 查看 Agent 日志中的 MCP 调用错误信息

### Q: MoE 模型无法使用

当前仅支持稠密模型。系统会自动检测 MoE/稀疏模型（Mixtral、DeepSeek-V2/V3、Qwen-MoE 等）并返回 `model_type=sparse`，前端提示不支持。

### Q: 如何手动新增模型到目录

通过 API 新增：

```bash
curl -X POST http://localhost:5000/api/model-catalog \
  -H "Content-Type: application/json" \
  -d '{
    "model_name": "MyModel-10B",
    "num_layers": 40,
    "d_model": 5120,
    "num_heads": 40,
    "d_ffn": 13824,
    "vocab_size": 32000,
    "description": "自定义稠密模型"
  }'
```

或从 HuggingFace 导入：

```bash
curl -X POST http://localhost:5000/api/model-catalog/fetch \
  -H "Content-Type: application/json" \
  -d '{"model_name": "meta-llama/Llama-2-7b-hf"}'
```

### Q: 如何重置内置模型种子

```bash
curl -X POST http://localhost:5000/api/model-catalog/seed
```

## 13. 开发与扩展

### 新增 Skill

在 `app/skills/` 下创建目录，继承 `SkillBase`，实现 `execute()` 方法，注册到 `registry`：

```python
# app/skills/my-new-skill/__init__.py
from app.skills.base import SkillBase, SkillContext, SkillResult

class MyNewSkill(SkillBase):
    name = "my-new-skill"
    description = "新技能描述"

    def execute(self, args: dict, context: SkillContext) -> SkillResult:
        # 实现逻辑
        return SkillResult(success=True, data=result)
```

Skill 会自动出现在 Agent 的工具列表中。

### 新增护栏规则

修改 `app/agent/guardrails.py` 中的 `validate_input_params` 或 `validate_topology_output`。

### 新增 API 端点

在 `app/routes/` 下创建 Blueprint，注册到 `app/main.py` 的 `create_app()` 中。

### 数据库增量补丁

在 `app/db_migration.py` 的 `SCHEMA_SQL` 中追加 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 或 `CREATE INDEX IF NOT EXISTS`，应用启动时自动执行。

# equivalent-modeling-service 使用指南

## 1. 产品概述

equivalent-modeling-service 是一款面向 AI 训练组网仿真测试的智能助手系统。它帮助测试人员：

- **输入组网参数** — 设备类型 (A2/A3/A5)、并行策略 (DP/TP/PP)、模型架构参数
- **生成组网拓扑** — 可视化原始组网与等效组网的 Mesh 结构
- **构建模型结构** — 自动生成 Transformer 模型层级描述
- **推送等效分析** — 逐条展示等效策略、计算指标与公式
- **执行仿真验证** — 通过 MCP 客户端下发仿真任务、实时监控进度
- **等效性判定** — 自动对比原始组网与等效组网仿真结果，输出结论

系统采用 **Flask 后端 + 静态前端 + OpenAI LLM + MCP 仿真** 的四层架构。

---

## 2. 系统架构

```
┌──────────────┐     SSE/REST/WS      ┌──────────────────────┐     JSON-RPC      ┌─────────────┐
│  前端 (SPA)   │ ──────────────────→ │  Flask Agent 后端     │ ──────────────→ │ MCP 仿真服务 │
│  index.html   │                      │  orchestrator + skills│                  │  (端口 9000) │
└──────────────┘                      └──────────────────────┘                  └─────────────┘
                                            │          │
                                      OpenAI API     PostgreSQL
                                      (LLM 推理)     (持久化)
```

核心组件：

| 目录 | 功能 |
|------|------|
| `app/routes/` | REST/WebSocket 路由（session、chat、simulation、model_catalog） |
| `app/agent/` | Agent 编排：orchestrator（LLM 驱动循环）、session（状态管理）、guardrails（护栏校验） |
| `app/skills/` | 注册式技能：组网生成、模型生成、仿真分析 |
| `app/mcp/` | MCP 客户端：JSON-RPC 调用仿真系统的任务下发/状态查询/结果获取 |
| `app/models/` | Pydantic 数据模型 + 模型目录（HuggingFace 远程解析） |
| `app/dao/` | PostgreSQL 数据访问层 |
| `static/` | 前端单页应用（HTML/CSS/JS + 拓扑渲染 + 仿真数据流） |

### 3.2 数据库（默认 SQLite，可选 PostgreSQL）

系统是**双后端**的，后端由 `DATABASE_URL` 的**前缀**自动判定，不需要额外的开关：

| 形态 | 使用场景 | 配置 |
|------|----------|------|
| **SQLite（默认）** | 本地开发、容器部署，**无需任何外部服务** | `DATABASE_URL` 留空；数据落在 `SQLITE_PATH`（默认 `/home/data/db/equivalent_modeling_service.db`） |
| **PostgreSQL（逃生门）** | 已有 PG 基础设施、需要多实例共享同一库 | `DATABASE_URL` 前缀为 `postgresql://` 或 `postgres://` |

> **前缀判定是静默的**：`DATABASE_URL` 非空但前缀不是这两种（例如写成 `postgres:/`、
> 用 `postgres@Data` 这类简写），程序**不会报错**，而是当作 SQLite 使用 ——
> 表现就是"数据丢了/看不到历史"。
> 排查时看启动日志里的 `(backend=sqlite|postgres)`，这是唯一可靠的确认方式。

**默认形态（SQLite）**：什么都不用配。

```bash
python -m app.db_migration      # 可选：只跑迁移建表，不启服务
```

**本地开发接本机 PostgreSQL**（逃生门）：

```sql
CREATE DATABASE equivalent_modeling_service;
```

**容器形态**（两个挂载点都必需，entrypoint 自动完成初始化）：

```bash
# 节点侧先准备好持久化目录并交出属主（容器以 uid 1000 运行）
sudo mkdir -p /data/aicm/db /data/aicm/workspace
sudo chown 1000:1000 /data/aicm/db /data/aicm/workspace

docker run -d --name equivalent-modeling-service \
  -v /data/aicm/workspace:/home/data/workspace \
  -v /data/aicm/db:/home/data/db \
  -p 5000:5000 <image>
```

容器内两个挂载点统一在 `/home/data` 下（`workspace` 与 `db`），节点侧各自独立目录。
仿真工具本体（`run.py` 等）在镜像内 `/home/aicm`，与数据挂载树**分置** ——
数据挂载与工具目录同名会让整目录挂载遮掉镜像层里的工具代码（工具被迫落到宿主机），
因此刻意分开：数据走 `/home/data` 挂载，工具留在镜像层 `/home/aicm`。

启动时 `docker/entrypoint.sh` 会按顺序完成：工作区自检 → DB 目录自检 → 拉起 MCP Server → 拉起 Flask（建表迁移 + seed）。**数据库文件不存在时由建表迁移直接创建** —— SQLite 按路径建库，因此既不需要 `initdb`，也不需要 `createdb`。

应用启动时自动执行建表迁移（`app/db_migration.py`），创建以下表：

| 表 | 用途 |
|----|------|
| `sessions` | 会话（步骤、任务 ID） |
| `topology_params` | 拓扑参数（DP/TP/PP、模型维度） |
| `simulation_params` | 仿真脚本与配置 |
| `simulation_results` | 仿真结果（cards JSON） |
| `comparison_reports` | 等效性对比报告 |
| `conversation_messages` | 对话消息记录 |
| `model_catalog` | 模型架构参数目录 |

**主键在两套后端下都是 UUID**，但生成方式不同：PG 侧用 `gen_random_uuid()` 作为列默认值（PG 13+ 内建，**不需要** `uuid-ossp` / `pgcrypto` 扩展）；SQLite 没有该函数，因此由 `app/dao` 在 Python 侧用 `uuid4()` 显式生成并写入。两套 DDL 的「表→列」映射由 `scripts/verify_static.py` 的 D1 断言强制保持一致。`IF NOT EXISTS` 保证重复执行安全；迁移结束时会对核心表与关键列做一次硬校验，缺失即让启动失败，不会以「半可用」状态带病运行。

#### 数据库持久化契约与约束

| 项 | 值 / 约束 |
|----|-----------|
| 容器内数据目录 | `/home/data/db`（挂载点），文件 `SQLITE_PATH=/home/data/db/equivalent_modeling_service.db` |
| 节点侧目录 | `/data/aicm/db`（`charts/values.yaml` 的 `database.nodePath`） |
| 挂载要求 | **必须是挂载点**。`docker/check_db.py` 会在启动时校验，未挂载直接 `exit 1` —— 绝不能容忍数据库静默写进镜像层（容器重建即丢全部会话历史） |
| 属主 / 权限 | 属主必须是容器运行用户（uid 1000），目录**可写**即可。K8s 下由 initContainer `chown` 保证 |
| 文件组成 | 主文件之外还有 `-wal` / `-shm` 两个伴生文件（WAL 模式）。**备份/搬迁要整目录拷**，只拷 `.db` 会丢最近事务 |
| 存储介质 | 必须落在**节点本地磁盘**。**不能**放 NFS —— SQLite 依赖本地文件锁与 `fsync` 语义 |
| 多副本 | 禁止。SQLite（WAL）是库级单写者，两个 Pod 同时打开同一文件会损坏数据（与 `sim-workspace` 的失效模式一致，`replicas` 必须为 1） |

> **停机行为**：entrypoint 在退出前会对 SQLite 执行一次 `wal_checkpoint(TRUNCATE)`，
> 把 `-wal` 中已提交的事务并回主文件，失败也不会阻止容器退出（见 `docker/checkpoint_db.py`）。
> 这一步是为了让运维侧「拷贝数据目录」能拿到完整快照，不是数据安全的前提。
>
> **从 PG 迁到 SQLite 时**：本次改造**不做**存量数据迁移；模型清单等由内置列表重新 seed，
> 是否需要搬运历史会话由使用方自行决定。方案与取舍见 `docs/PG迁移SQLite改造计划.md`。

### 3.3 MCP 仿真服务

| `report_status` | 查询任务状态与进度 |
| `sync_logs` | 增量同步仿真日志 |
| `get_result` | 获取完整仿真结果 |
| `card_detail` | 获取每卡仿真指标 |
| `get_device_detail` | 获取设备算子追踪与时间线 |
| `get_hbm_detail` | 获取 HBM 使用量拆解 |
| `get_comm_detail` | 获取 TP/PP/DP 通信详情 |

## 5. 启动服务

**本地开发**（默认数据库是内嵌 SQLite，无需任何外部服务；只需 MCP 仿真服务）：

```bash
# 确保 MCP 仿真服务已启动（数据库随 Flask 进程自动就绪）
python -m app.main
```

**容器方式**（数据库随容器内嵌，无需外部 PG）：

```bash
docker run -d --name equivalent-modeling-service \
  -v /data/aicm/workspace:/home/data/workspace \
  -v /data/aicm/db:/home/data/db \
  -p 5000:5000 <image>
```

容器启动即自动完成 目录自检 → 建表迁移 → seed，日志中可见 `[entrypoint]` / `[migration]` 各阶段进度（见 §3.2）。两个挂载目录都**必须有**，缺失时容器会明确报错退出，而不是静默把数据写进镜像层。

服务启动后访问 `http://localhost:5000` 即可打开前端界面。

> 只做本地验证、暂不想挂载数据目录时，可加 `-e DB_ALLOW_LOCAL=1` 豁免数据库目录的挂载点自检（会打印醒目告警；`/home/data/workspace` 一侧同理可用 `AICM_MCP_WORKSPACE_ALLOW_LOCAL=1`）。

### 5.1 走 nginx 子路径访问（如 `http://<host>/ftbot/equivalent/`）

应用支持被反向代理挂在任意子路径下，**无需按环境改代码**：

```nginx
location /ftbot/equivalent/ {
    proxy_pass http://7.185.127.30:38088/;   # 尾斜杠剥掉前缀后转发，必须保留
}
```

前端所有地址都从当前文档地址推导（`static/index.html` 的 `APP_BASE`，单一事实来源）：
资源用相对路径 `static/xxx`、接口用 `APP_BASE + "/api"`、WebSocket 用
`location.host + APP_BASE + "/ws/simulation/<id>"`。所以 `/` 与 `/ftbot/equivalent/`
两种部署形态共用同一份前端。后端收到的始终是 `/`、`/api/...`、`/static/...`、`/ws/...`，
**不需要** `SCRIPT_NAME` / `X-Forwarded-Prefix` / `ProxyFix` 配合。

除 `proxy_pass` 之外还有几项必配（缺一项对应功能就不可用）：

| 配置 | 缺了会怎样 |
|------|-----------|
| `location = /ftbot/equivalent { return 301 /ftbot/equivalent/; }` | 访问不带尾斜杠的前缀匹配不到 `location /ftbot/equivalent/` → 404 |
| `proxy_set_header Upgrade $http_upgrade;` + `Connection $connection_upgrade` | WebSocket `/ws/simulation/<id>` 握手失败（仿真进度不刷新） |
| `proxy_buffering off;` | SSE 被 nginx 攒成一坨，逐行推送变成「长时间不动后一次性刷出」 |
| `proxy_read_timeout 3600s;` | 默认 60s 读超时掐断 LLM 长回答 / 长任务轮询 |
| 端口用宿主映射 `-p 38088:5000`，容器内保持 `FLASK_PORT=5000` | 改容器内端口会让 `HEALTHCHECK`（写死探测 5000）判定容器不健康 |

## 7. 工作流程

Agent 驱动四步工作流，每步等待用户确认后推进：

### Step 1 — 等效参数设定

1. 用户输入组网参数（设备类型、DP/TP/PP）和模型名称
2. **模型参数自动填充**：Agent 调用 `auto_fill_model_params`，通过 HuggingFace → ModelScope → 内置表的四级解析链获取模型架构参数 (L/H/A/dff/V)，推送到前端表单
3. 护栏静默校验参数合法性
4. 调用 `training-mesh-gen-skill` 生成原始组网拓扑
5. 调用 `training-model-gen-skill` 生成原始模型结构
6. 前端渲染组网图 + 模型层级图

### Step 2 — 等效计算推导

1. 用户确认等效计算
2. Agent 逐条推送等效策略、计算指标、公式（`emit_formula_line`），前端逐行渲染
3. 计算等效组网参数（调整 PP/DP/层数等）
4. 生成等效组网拓扑 + 等效模型结构
5. 前端渲染等效组网图

### Step 3 — 等效仿真验证

1. 用户确认下发仿真
2. MCP 客户端下发仿真任务（原始 + 等效）
3. WebSocket 实时推送仿真状态与进度
4. 仿真完成后获取每卡指标（FLOPs、HBM、TP/PP/DP 通信量）

### Step 4 — 等效方案输出

1. 自动对比原始与等效仿真结果
2. 计算各指标差异百分比（容忍度 5%）
3. 输出等效性结论：✅ 通过 或 ❌ 不通过

## 8. 模型参数解析

模型架构参数的获取采用四级解析链（`resolve_model_config`）：

| 级别 | 来源 | 说明 |
|------|------|------|

## 9. 护栏校验

输入护栏（`validate_input_params`）在 Agent 调用工具时静默执行：

- **设备类型**：仅允许 A2、A3、A5
- **DP 范围**：1–1024（>512 发警告）
- **TP 范围**：1–32（非 2 的幂次发警告）
- **PP 范围**：1–128
- **总节点数**：= DP × TP × PP，>10000 发警告

输出护栏（`validate_topology_output`）校验生成拓扑的一致性：

- 节点数 = `total_nodes` = DP × TP × PP
- 通信域分组大小与并行度匹配

## 11. 数据模型概览

### 会话状态 (`SessionState`)

```
session_id          — 会话标识 (8字符 UUID)
step                — 当前阶段: idle | params_collected | equiv_calculating | equiv_generated | simulating | completed
original_params     — 原始拓扑参数
equivalent_params   — 等效拓扑参数
original_topology   — 原始组网拓扑 (MeshTopology)
equivalent_topology — 等效组网拓扑
original_training_model   — 原始模型结构 (TrainingModel)
equivalent_training_model — 等效模型结构
original_simulation  — 原始仿真结果 (SimulationResult)
equivalent_simulation — 等效仿真结果
comparison_report   — 对比报告 (ComparisonReport)
simulation_params   — 仿真配置 (SimulationParams)
history             — 对话历史
```

### 组网拓扑 (`MeshTopology`)

```
name             — 组网名称
device_type      — A2 / A3 / A5
total_nodes      — 总节点数 = DP × TP × PP
dp_size / tp_size / pp_size
nodes            — 节点列表 (MeshNode: id, device_type, dp_rank, tp_rank, pp_rank, global_rank)
communication_groups — 通信域分组 {dp: [...], tp: [...], pp: [...]}
```

> **Rank 布局（与仿真系统一致，TP-DP-PP）**：`global_rank = pp_rank*(tp*dp) + dp_rank*tp + tp_rank`
> 即 TP 最低位、DP 居中、PP 最高位。唯一实现见 `app/rank_layout.py`，前端镜像见
> `static/topo-renderer.js` 的 `meshRankOf` / `meshDecomposeRank`。转换函数：
> ```
> tp_rank = global_rank % tp
> dp_rank = (global_rank // tp) % dp
> pp_rank = global_rank // (tp * dp)
> ```

### 每卡指标 (`CardMetrics`)

```
card_id / global_rank
flops_per_card   — 单卡 FLOPs
hbm_gb           — HBM 总占用
hbm_model_gb     — 模型显存占用 (权重+梯度+优化器)
tp_comm_gb_per_micro  — TP 通信量
pp_comm_mb_per_micro  — PP 通信量
dp_comm_gb_per_step   — DP 通信量
```

### 等效性报告 (`ComparisonReport`)

```
flops_diff_pct / hbm_diff_pct / tp_comm_diff_pct / pp_comm_diff_pct / dp_comm_diff_pct
is_equivalent    — 是否等效 (所有指标差 ≤ 5%)
error_tolerance_pct — 容忍度阈值 (默认 5%)
details          — {conclusion: "✅/❌", max_diff_pct: ...}
```

## 12. 常见问题

### Q: 启动时报数据库连接失败

先判断当前是哪种形态（最可靠的办法是看启动日志里的 `(backend=sqlite|postgres)`）：

**默认形态（SQLite）**：问题几乎总是「数据文件所在目录不可写或不存在」。

| 现象 | 原因 | 处理 |
|------|------|------|
| `unable to open database file` | `SQLITE_PATH` 的**父目录**不存在或不可写 | 建目录并给写权限；确认磁盘未满 |
| `database is locked` | 有另一个进程/副本同时写（WAL 仍是库级单写者） | 确认没有两个 Flask 实例共用一个数据文件；必要时调大 `SQLITE_BUSY_TIMEOUT_MS` |
| `database disk image is malformed` | 文件放在 NFS/SMB 等不支持正确文件锁的存储上，或拷走了 `-wal` 但没拷主文件 | 换到节点本地磁盘；从完整目录副本恢复 |

**逃生门形态（PostgreSQL）**：确保 PG 已启动、`DATABASE_URL` 前缀正确、库已存在。连接池默认 2–10 连接（`app/db.py`），建池带有限重试（`DB_CONNECT_RETRIES`，默认 10 次 × 1.5s），日志里会打印连接目标。

**与数据库无关但极易混淆的一条**：若 Agent 首次调用大模型时报
`httpx.InvalidURL: Invalid port: ':1]'`，这与数据库无关，而是运行环境的 `NO_PROXY`
含**方括号 IPv6** 写法（如 `NO_PROXY=localhost,127.0.0.1,::1,[::1]`）。httpx 0.28 在
构造 `URLPattern` 时无法解析该值，而 `app/agent/orchestrator.py` 用
`httpx.Client(verify=..., proxy=...)` 构造 OpenAI 客户端，于是请求尚未发出就抛错。
处理：把 `NO_PROXY` 改为 `localhost,127.0.0.1,::1`（去掉 `[::1]`）后重启进程。

**容器形态**：按顺序排查下面几条，日志中每一步都有 `[entrypoint]` / `[db-check]` 前缀：

| 现象 | 原因 | 处理 |
|------|------|------|
| `not a mount point` 并退出 | `/home/data/db` 未挂载 | 按 §5 加 `-v /data/aicm/db:/home/data/db`；K8s 检查 `database.nodePath` 与 hostPath 卷 |
| `目录不可写` | 宿主机目录权限/属主不对 | `sudo chown -R 1000:1000 <nodePath>`；K8s 下由 initContainer 自动完成 |
| `数据库 schema 不完整，拒绝以半可用状态启动` | 建表迁移有失败项 | 报错里会列出缺失的表/列与失败语句；SQLite 下常见于目录不可写，PG 下常见于缺少 DDL 权限 |

手动检查数据的两种方式（默认 SQLite）：

```bash
# 列出表
docker exec <container> python -c "import sqlite3,os; c=sqlite3.connect(os.environ.get('SQLITE_PATH','/home/data/db/equivalent_modeling_service.db')); print([r[0] for r in c.execute(\"SELECT name FROM sqlite_master WHERE type='table'\")])"

# 进交互式 sqlite3（如镜像内装了 CLI；没有就用上面的 python -c）
docker exec -it <container> sqlite3 /home/data/db/equivalent_modeling_service.db '.tables'
```

逃生门形态改用 `psql -U postgres -d equivalent_modeling_service -c '\dt'`。

### Q: 模型参数填充失败

1. 检查网络是否可访问 HuggingFace (`huggingface.co`)
2. 尝试使用完整仓库 ID（如 `Qwen/Qwen2.5-7B`）而非裸名
3. 裸名会先搜索 HF 匹配官方仓库，再走远程获取
4. 最终兜底为内置种子表

### Q: 仿真任务下发失败

1. 确认 MCP 仿真服务已在 `MCP_SERVER_URL` 端口启动
2. 检查服务健康状态：`GET <MCP_SERVER_URL>/health`
3. 查看 Agent 日志中的 MCP 调用错误信息

### Q: MoE 模型如何使用

MoE/稀疏模型（Mixtral、DeepSeek-V2/V3、Qwen-MoE 等）已支持：

1. 模型目录会返回 `model_type=sparse` 及专家数 / Top-K / MoE 层数 / 专家 FFN 维度 / 共享专家等专用参数
2. Step1 表单需再填 **EP（专家并行度）**；EP 必须能整除专家数，且 `EP ≤ DP × TP`
3. 下发仿真时 MoE 参数随 topology 传给 MCP Server，脚本按 MoE 语义生成
   （`--num-experts` / `--moe-router-topk` / `--moe-layer-freq` / `--moe-ffn-hidden-size` 等）
4. `card_detail` 对 MoE 任务额外返回 EP 通信量（`ep_comm_gb_per_step`），
   `get_comm_detail` 支持 `comm_type="ep"`（EP 通信取自仿真输出的 `ep_group` 域；
   `ep=1` 时为 0，因为专家通信都在卡内完成）

### Q: 挂在 nginx 子路径下，页面能打开但一片空白 / 控制台全是 404

典型是**前缀丢失在浏览器侧**：nginx 用 `proxy_pass http://host:38088/;`（尾斜杠）把
`/ftbot/equivalent/` 剥掉后转发，后端只认 `/api`、`/static`、`/ws`；如果前端里出现
**根绝对路径**（写死 `/api`、`/static/...`、`/ws/simulation/...`），浏览器就会把这些
请求打到 nginx 根上，而那里没有本应用的 location → 全 404。

排查顺序：

1. 看 HTTP 状态：`/ftbot/equivalent/` 若是 404 → 少了尾斜杠（补
   `location = /ftbot/equivalent { return 301 /ftbot/equivalent/; }`）；
   页面 200 但资源 404 → 前缀问题。
2. 用开发者工具 Network 看请求的**实际路径**：出现 `http://<host>/api/...`（不带前缀）
   即为该问题。前端地址一律由 `static/index.html` 的 `APP_BASE` 推导
   （资源为相对路径 `static/xxx`），**不要在 HTML/JS 里新写 `/api` 或 `/static/` 开头的绝对路径**。
3. 仿真进度条不动 / 长回答中途断：检查 `proxy_set_header Upgrade`、
   `proxy_buffering off`、`proxy_read_timeout 3600s`（见 §5.1）。

## 13. 开发与扩展

### 新增 Skill

在 `app/skills/` 下创建目录，继承 `SkillBase`，实现 `execute()` 方法，注册到 `registry`：

```python
# app/skills/my-new-skill/__init__.py
from app.skills.base import SkillBase, SkillContext, SkillResult

class MyNewSkill(SkillBase):
    name = "my-new-skill"
    description = "新技能描述"

    def execute(self, args: dict, context: SkillContext) -> SkillResult:
        # 实现逻辑
        return SkillResult(success=True, data=result)
```

Skill 会自动出现在 Agent 的工具列表中。

### 新增护栏规则

修改 `app/agent/guardrails.py` 中的 `validate_input_params` 或 `validate_topology_output`。

### 新增 API 端点

在 `app/routes/` 下创建 Blueprint，注册到 `app/main.py` 的 `create_app()` 中。

### 数据库增量补丁

在 `app/db_migration.py` 的 `SCHEMA_SQL` 中追加 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 或 `CREATE INDEX IF NOT EXISTS`，应用启动时自动执行。

两点约定：

1. **不要**把一次性历史清理写成 `ALTER TABLE ... DROP COLUMN IF EXISTS`。这类语句每次启动都会重新执行（白拿表锁），需要清理旧库时手工执行一次即可。
2. 新增「关键表/列」时，同步把表名加到 `REQUIRED_TABLES`、把最容易被漏掉的列加到 `REQUIRED_COLUMNS`。收尾硬校验靠这两个元组判断 schema 是否完整——漏加会让校验形同虚设。
